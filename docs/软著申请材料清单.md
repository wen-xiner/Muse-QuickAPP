## 三、关键注意事项（踩坑清单）

1. **三处一致**：申请表、源程序页眉、说明书封面上的软件名称 + 版本号必须完全一致。
2. **不要交依赖和构建产物**：审查只认源代码，node_modules/dist 会显得不专业且行数虚高。
3. **著作权人主体确认**：团队叫"灯塔象限"，但软著申请人必须是自然人（或法人）。如果是团队协作，建议：
   - 方案 A：以你个人名义申请（最省事，后续转让/授权灵活）
   - 方案 B：成员共同申请（需全员信息，周期稍长）
   - 建议先定方案 A，证书下来后可再申请变更。
4. **隐私政策页缺失**：青少年 + AI + 危机热线场景，说明书第 5 章和产品页都应该有隐私说明。软著不强制，但上架/宣传时是硬性材料，建议本次一并补一个简单的隐私政策页。
5. **README 过时**：README 还写着"AIGC创新大赛-复赛阶段"、项目类型"快应用"，与现状不符。建议更新后再截图/引用（说明书若引用 README 内容会穿帮）。
6. **LICENSE 缺失**：README 标了 MIT 但没有 LICENSE 文件，整理时补上。
7. **加急 vs 普通**：不着急就拿普通免费；若学校/简历有 deadline，再考虑加急（官网有加急通道，费用数百元）。
8. **一人一证原则**：软著按"软件"计数，不限制个人数量，但名称不能与已登记软件重名（检索确认"心屿 Muse"无冲突）。
